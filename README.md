# MangoRestaurant

**MangoRestaurant** --- учебный проект интернет-магазина/ресторана,
разрабатываемый с использованием микросервисной архитектуры. Проект
предназначен для практики проектирования backend-систем, разделения
ответственности между сервисами и взаимодействия компонентов по HTTP.

Пользовательский интерфейс будет реализован на **ASP.NET Core MVC** ---
в первую очередь для наглядной демонстрации работы микросервисов.

## Цели проекта

-   Изучить и применить микросервисный подход на практическом проекте.
-   Разделить приложение на независимые сервисы с собственными зонами
    ответственности.
-   Организовать взаимодействие между сервисами через HTTP API.
-   Разделить внутреннюю архитектуру каждого сервиса на отдельные слои.
-   Реализовать MVC-приложение, которое будет обращаться к API сервисов.
-   Практиковать работу с ASP.NET Core, Entity Framework Core и SQL
    Server.

## Технологии

Основной набор технологий проекта:

-   **C# / .NET / ASP.NET Core**
-   **ASP.NET Core Web API** --- API микросервисов.
-   **ASP.NET Core MVC** --- пользовательский интерфейс.
-   **Entity Framework Core** --- доступ к данным.
-   **Microsoft SQL Server** --- реляционная база данных.
-   **AutoMapper** --- преобразование моделей и DTO.
-   **Swagger / OpenAPI** --- описание и тестирование HTTP API.

Список технологий будет дополняться по мере развития проекта.

## Архитектура решения

На верхнем уровне решение разделяется на пользовательское MVC-приложение
и микросервисы.

``` text
MangoRestaurant/
│
├── Mango.Web/                         # ASP.NET Core MVC — пользовательский интерфейс
│
├── Services/
│   └── Mango.Services.ProductAPI/     # Микросервис товаров
│       ├── API (PL)/                  # HTTP-контроллеры, DTO, Middleware
│       ├── Application (BLL)/         # Бизнес-логика, модели, контракты
│       └── Data/                      # EF Core, DbContext, сущности и конфигурации
│
├── README.md
└── ...
```

> Структура является целевой и может изменяться по мере развития
> проекта. Названия каталогов и проектов могут быть уточнены.

### Микросервисы

Каждый микросервис отвечает за отдельную предметную область и
предоставляет собственный API.

На текущем этапе разрабатывается:

  -----------------------------------------------------------------------------
  Сервис                        Назначение              Статус
  ----------------------------- ----------------------- -----------------------
  `Mango.Services.ProductAPI`   Управление товарами:    В разработке
                                получение, создание,    
                                изменение и удаление    

  -----------------------------------------------------------------------------

Другие сервисы будут добавляться по мере необходимости. Каждый новый
сервис должен иметь чётко определённую ответственность и не должен
напрямую обращаться к внутренним сущностям или базе данных другого
сервиса.

### Внутренняя архитектура микросервиса

Для микросервисов используется разделение на три логических слоя:

#### API (PL) --- Presentation Layer

Отвечает за взаимодействие с внешним миром:

-   HTTP-контроллеры и маршрутизация.
-   Приём и проверка входящих запросов.
-   DTO для входящих и исходящих данных.
-   Преобразование DTO и моделей приложения.
-   Формирование HTTP-ответов.
-   Middleware для обработки исключений.
-   Регистрация зависимостей и конфигурация приложения.

#### Application (BLL) --- Business Logic Layer

Отвечает за прикладную и бизнес-логику:

-   Сервисы и сценарии работы с данными.
-   Интерфейсы и контракты.
-   Модели приложения.
-   Проверка бизнес-правил.
-   Координация операций.

#### Data --- Data Access Layer

Отвечает за хранение и получение данных:

-   Entity Framework Core.
-   `DbContext`.
-   Сущности базы данных.
-   Конфигурации сущностей.
-   Миграции и взаимодействие с SQL Server.
-   Реализация доступа к данным.

**Направление зависимостей** должно оставаться контролируемым: API
вызывает прикладную логику, а прикладная логика использует необходимые
механизмы доступа к данным через определённые контракты. По мере
развития проекта границы и зависимости слоёв будут уточняться.

## Взаимодействие компонентов

Предполагаемый поток запроса:

``` text
Пользователь
    │
    ▼
ASP.NET Core MVC
    │
    │ HTTP
    ▼
Микросервис API
    │
    ▼
Application / BLL
    │
    ▼
Data / DAL
    │
    ▼
SQL Server
```

MVC-приложение выступает клиентом API и не должно напрямую обращаться к
таблицам или `DbContext` микросервисов.

Межсервисное взаимодействие также планируется выполнять через публичные
контракты API, а не через прямой доступ к базам данных соседних
сервисов.

## Основные принципы разработки

-   **Разделение ответственности:** у каждого слоя и микросервиса своя
    зона ответственности.
-   **Инкапсуляция данных:** внутренняя модель БД не должна
    автоматически становиться публичным API-контрактом.
-   **DTO:** входящие и исходящие HTTP-модели отделены от внутренних
    моделей приложения и сущностей БД.
-   **Dependency Injection:** зависимости регистрируются в точке
    композиции приложения.
-   **Обработка ошибок:** единый механизм обработки непредвиденных
    исключений; клиенту не передаются stack trace и внутренние сведения
    приложения.
-   **Асинхронность:** асинхронные операции ввода-вывода выполняются с
    использованием `async` / `await`.
-   **Конфигурация:** строки подключения и настройки окружения хранятся
    в конфигурации, секреты не коммитятся в Git.
-   **Независимость микросервисов:** сервисы взаимодействуют через API и
    не используют напрямую внутренние классы друг друга.
